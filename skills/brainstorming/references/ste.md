# Simplified Technical English

ASD-STE100 is a controlled language for technical documents. Issue 9 (2025) has 53 writing rules and a dictionary of about 900 approved words. The dictionary is
not in this repository. Apply the rules below. For words, use the simplest common word, and use one word for one thing.

## Words

- Use one word for one meaning. Do not use a synonym for a thing that already has a word.
- Use a technical name for a thing of the project: a glossary term, a class, a file, a message. Do not translate a technical name.
- Do not use a technical name as a verb. Do not use a verb as a noun.
- Do not use slang or jargon.
- Use the spelling of the repository. This repository uses British spelling.

## Noun phrases

- Write a noun cluster of not more than three nouns.
- Put an article or a demonstrative before a noun: the design, this rule.

## Verbs

- Use only these verb forms: infinitive, imperative, simple present, simple past, simple future.
- Use the past participle only as an adjective: an approved design.
- Do not use the "-ing" form of a verb, except in a technical name: brainstorming, writing-plans.
- Do not use helping verbs to make a complex verb structure. Write "the test fails", not "the test would have failed".
- Use the active voice. In a description, use the passive voice only when the doer is not known.
- Use a verb for an action. Write "decide", not "make a decision".

## Sentences

- Write one instruction in each sentence.
- Write not more than 20 words in an instruction. Write not more than 25 words in a descriptive sentence.
- Do not omit a word to make a sentence shorter. Do not use a contraction.
- Use a vertical list for complex text.
- Use a connecting word to connect two sentences with related topics.
- Do not use the semicolon.

## Paragraphs

- Write one topic in each paragraph.
- Write not more than six sentences in each paragraph.
- Start the paragraph with the sentence that states its topic.

## Procedures

- Write an instruction in the imperative: "Ask one question."
- When a condition comes before an instruction, divide it from the command with a comma: "If the user brings a design, apply the ADR test first."
- Write a note to give information, not to give an instruction.
- Write positively. Say what to do, not what not to do, when a positive instruction is possible.

## Warnings

- Start a warning with a clear command or condition. Then give the risk or the possible result.

## Check your text

- Count the words of each sentence.
- Count the sentences of each paragraph.
- Find each "-ing" word, each semicolon and each passive sentence. Change them.
